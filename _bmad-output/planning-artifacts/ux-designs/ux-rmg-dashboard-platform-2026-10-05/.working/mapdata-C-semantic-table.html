Exploration C

Assign roles, then auto-fill slots

This follows the product owner's mental model. Admins first say what each field means: Time, Measure, Dimension, Filter/Category, Value or Label. They do this on a plain table of real sample rows, so they see the data and not JSON. Dashflow then fills the block's slots from those roles. It shows a confidence note for each guess and an override link on every slot. Because the roles don't depend on the block type, switching from KPI & Chart to another block type can re-fill the slots without asking the admin again.

Trade-off: best for tabular, well-named APIs and for teams that reuse one endpoint across several block types / weaker when the response has no clean record array, or when two fields share a role (two Values, two Measures), so the auto-fill guesses and the admin has to check them.
