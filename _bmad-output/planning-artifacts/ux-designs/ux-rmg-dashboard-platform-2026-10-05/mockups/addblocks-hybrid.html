1Inline expansion, not a modal

Clicking the row body, or pressing Enter on a focused row, expands it in place, like an accordion. Only one row is open at a time. The rows above keep their scroll position, and the dashboard stays visible next to the drawer.

The preview renders the block’s real component with sample data at about 340px wide. That is large enough to tell two similar charts apart, which the 64px thumbnail cannot do. The metadata line answers “Can I trust this?”: Data source: HR analytics API · Refreshes hourly · v1.0. The default size tells users how much free space the block needs.

The + Add to dashboard button follows the same rule as + Add on the row: the block goes into the first free slot. Then the row collapses and shows “✓ Added”. Esc collapses the preview first. A second Esc closes the drawer.

The row element uses aria-expanded. The preview is a region labelled “Preview of Team Performance with sample data”.

Tap outside or Done to close

Below about 1024px the drawer overlays the dashboard

On small screens there is no room to push the dashboard. The sheet covers the full height and leaves a 28px strip of dimmed dashboard on the left. Tapping that strip closes the sheet, the same as Done. Here the sheet is a true modal: focus is trapped and the background is inert.

The chips scroll sideways and fade at the edge. Thumbnails shrink to 52×38, and descriptions stay on one line.

After + Add, the toast appears inside the sheet, because the dashboard is hidden. Show me closes the sheet, scrolls to the new block and pulses its outline. On a single-column phone layout, the first free slot is the end of the dashboard.

Adding a block without dragging

  1. Open the drawer with + Add block (Enter). Focus moves to the search field.
  2. Type to filter, then ↓/↑ to move between rows (roving tabindex).
  3. A on a row, or Tab to + Add and press Enter, adds the block to the first free slot. A polite live region says where it went.
  4. Enter on the row opens the inline preview.
  5. To reposition the block afterwards, focus it on the dashboard, press M, then use the arrow keys. Shift+arrows resizes it.

Focus order in the drawer

  1. Close ×
  2. Search
  3. Category chips (one tab stop, arrow keys between chips)
  4. Filter
  5. List (one tab stop, arrow keys between rows, Tab into the row’s action)
  6. Done

The wide-screen drawer is non-modal, so F6 moves focus between the dashboard and the drawer. The toast’s Show me / Undo can be reached with F6, and it stays open while it has focus.

Closing

  • Esc collapses an open preview first. Otherwise it closes the drawer.
  • Focus returns to the + Add block button, or to the last block added if the user chose Show me.
  • The dashboard reflows back to full width. Blocks keep their positions.

Design tensions to resolve

  • At 1280px the dashboard is only 1280 − 232 − 392 = 656px wide. Four KPIs at about 150px each start to truncate values, and the 2-up blocks are about 320px, which is too narrow for chart axes. Option: collapse the app sidebar to a 64px icon rail while the drawer is open, which gives back 824px. Option: overlay below about 1280px instead of below 1024px.
  • Reflow versus “never rearranged”. When the dashboard switches breakpoint, blocks visibly shift columns, even though their stored positions do not change. The first free slot has to be computed in the stored (wide) layout and then mapped to the narrow view. Otherwise a block can look placed in a gap and then land somewhere else when the drawer closes.
  • Thumbnails at 64px show only the shape (KPI, chart, list, progress). Two bar charts look the same, so the inline preview still matters.
  • Free-space hint. Showing the next slot (frame 1) makes placement predictable, but it adds visual noise. Show it only on hover or focus of + Add?
