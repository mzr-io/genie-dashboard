- (decision) Paradigm PROPOSED: modular monolith (one Laravel codebase, hexagonal modules with ports/adapters) + pipes-and-filters data pipeline (Connector -> Raw Store -> Dataset/Mapping -> Transform executor -> Block Result -> Dashboard API). Multiple process roles (web, connector-worker, compute-worker, scheduler, realtime) from one image; no microservices. Alternatives weighed: microservices (rejected: team size, MVP), monolith without module boundaries (rejected: connector security boundary + future agent need seams)
- (decision) CQRS-lite read path PROPOSED: dashboards read materialized Block Results only; dashboard requests never call external APIs synchronously. Cold miss -> loading state + enqueue sync; result pushed. Prevents coupling API availability to dashboard requests
- (decision) Fetch Key PROPOSED: hash(workspace, endpoint id + endpoint config revision, resolved params incl period window, user-context values). Unit of sharing, dedupe, scheduling, change detection, raw storage. Demand-driven scheduling: keys with active viewers / recent access are refreshed at the min Refresh Interval of subscribing blocks; idle keys go cold
- (decision) Connector security boundary PROPOSED: all outbound calls to source APIs (scheduled sync, wizard Test, Fetch sample, publish validation) execute only in connector-worker processes via a FetchRequest/FetchResponse message contract; web nodes never call source APIs and never decrypt credentials. Same contract later carried by the on-prem agent transport
- (decision) Change detection order PROPOSED: ETag/If-None-Match -> Last-Modified/If-Modified-Since -> content hash (sha256 of canonical JSON) when neither header exists. Unchanged => update checked_at only, keep data_as_of, skip recompute
- (decision) Raw store PROPOSED: immutable raw payload per successful fetch, keyed by fetch key + content hash, stored in PostgreSQL behind a RawStore port (object-storage driver later); retention policy per Data Source: latest-only (default, = durable last-known-good) or N-day window (opt-in). Block Results are derived and recomputable from (raw payload, block version) -> remap without refetch. Pending user decision on C1
- (decision) Dataset layer PROPOSED (reconciles C2): Dataset = Endpoint + Record Path + typed Field catalog (path, type, default role, record-key flag), created implicitly by the wizard and reused across Blocks; Block Version holds Slot Mapping + transforms + calculated fields referencing dataset fields. Governed metric = the expression AST inside a published Block Version in MVP; dataset-scoped Metric catalog post-MVP using the same AST format
- (decision) Transform engine PROPOSED: declarative Query Plan (AST JSON) is the only form transforms take; MVP executor = in-process PHP over extracted rows with guards; future executor = SQL over normalized rows (history) behind the same port.
