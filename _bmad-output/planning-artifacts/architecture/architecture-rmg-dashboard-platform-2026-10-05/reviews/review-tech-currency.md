# Review: Tech Currency (2026-10-05)

**Scope:** ARCHITECTURE-SPINE.md and SOLUTION-DESIGN.md. The question for every committed technology claim: was it web-verified or checked against reality, or only asserted?
**Baseline evidence:** research/tech-verification-2026-10-05.md, which covers versions, licences and the starter-kit package.json.
**This review:** 16 claims that the evidence file does not cover, checked live against official docs and registries on 2026-10-05.

## Verdict

The stack is current and every named technology exists. The architecture's version table matches the evidence file. None of the 16 extra claims is outright false. Three are imprecise in ways that will bite at scaffold time:

1. Sanctum and Pest are not in the starter kit.
2. Inertia 3 no longer ships axios, which affects Sanctum SPA CSRF handling for the `/api/v1` calls.
3. Horizon does not support Redis/Valkey **Cluster** mode, which constrains which managed Valkey offerings fit.

Two claims are misattributed but harmless: "Horizon unique jobs" and `schedule:work` used in production.

| 10 | PgBouncer transaction mode compatible with `SET LOCAL` (SD §10.1) | **Verified, with caveats** | Plain `SET`/`RESET`, session advisory locks, `LISTEN` and SQL `PREPARE` are "Never" supported. | 14 | Starter kit auth scaffolding (SD §3 Identity, §10.2) | **Verified: uses Fortify** | All L13 starter kits use **Laravel Fortify** (`^1.37`) for login, registration, password reset, email verification, password confirm and **2FA, which is on by default**. They also use **Wayfinder** (typed routes; disabling a Fortify feature means removing frontend route references) and an optional **Teams** scaffold. The architecture doesn't mention Fortify, Wayfinder or Teams. Decide explicitly: disable `Features::registration()` (users join by invitation), decide whether 2FA stays, don't generate the Teams scaffold (Workspaces are the platform's own model). Fortify's table is `password_reset_tokens`, not the `password_resets` named in SD §3. | https://laravel.com/docs/13.x/starter-kits |
| 15 | Scheduler: sub-minute dispatch, single leader (SD §6.5, §15) | **Verified, with note** | `everySecond()`…`everyThirtySeconds()` exist. `onOneServer()` needs a `database`/`redis`/`memcached`/`dynamodb` cache. Running `schedule:work` as a long-lived container process is common and works, but it's not the documented production mode. The custom dispatcher loop with a Valkey leader lock is outside the Laravel scheduler, which is fine. Alternatively, express it as `Schedule::job(...)->everyFiveSeconds()->onOneServer()` and drop the hand-rolled leader lock. | https://laravel.com/docs/13.x/scheduling |

The official Horizon docs say only "requires Redis" and "**not compatible with Redis Cluster**". So managed Valkey in **cluster mode** (e.g. ElastiCache Serverless or cluster-mode-enabled) won't work for Horizon queues. The architecture's "any Redis-compatible store accepted" needs the qualifier "non-cluster (primary/replica) for the queue connection". | https://laravel.com/docs/13.x/horizon ; https://docs.vultr.com/monitoring-laravel-queues-with-horizon-and-vultr-managed-databases-for-valkey |

## Other currency observations

- **Version table (Spine §Stack):** every row matches the evidence file. Missing rows: **Pest 5.x**, **Laravel Fortify 1.x**, **Laravel Wayfinder 0.1.x**, **ext-bcmath**, **PgBouncer ≥ 1.21** (if used), and the frontend **HTTP client** for `/api/v1` (Inertia `useHttp`, `fetch`, or axios added back).
- **UUIDv7 generation (Spine AD-10):** the Spine says "generated by the platform" and also "`uuidv7()` in PG18". Laravel's `HasUuids` also generates IDs app-side. Pick one source (DB default vs Eloquent), or IDs will come from two generators. This is not a currency problem, but the claim is ambiguous. *(Laravel's current `HasUuids` UUID version was not re-verified here.)*
- **TypeScript 5.x pin:** still correct. The starter kit pins ^5.2, and TS 7 / vue-tsc compatibility is still unverified (already flagged in the evidence file).

## Recommended fixes (none applied; architecture files not edited)

1. AD-20 / SD §10.2: name the `/api/v1` HTTP client. With Inertia 3 there's no axios, so either add axios with `withXSRFToken` or send `X-XSRF-TOKEN` in a `fetch` wrapper. Add `install:api` (Sanctum) as a scaffold step.
2. SD §11 / §19 / §17: "Horizon requires a non-cluster Redis-protocol endpoint for queues." Qualify "any Redis-compatible store".
3. SD §6.4 / §16: change "Horizon unique jobs" to "framework `ShouldBeUnique` (not applied inside batches)". The duplicate-delivery row should cite idempotency.
4. SD §3 / §10.2: say that auth comes from Fortify via the starter kit, with registration disabled, the 2FA decision recorded, and no Teams scaffold. Rename `password_resets` to `password_reset_tokens`.
5. Spine §Stack: add Pest 5.x (needs PHPUnit 13, so replace the starter kit's PHPUnit 12), Fortify, Wayfinder and ext-bcmath.
6. SD §10.1: add the PgBouncer prepared-statement note (`max_prepared_statements`) and the `current_setting(..., true)` fail-closed form.
7. SD §4 `scheduler` row: either document `schedule:work` as a deliberate long-running choice, or use cron + `schedule:run` + `schedule:interrupt`. Consider `->everyFiveSeconds()->onOneServer()` in place of the hand-rolled leader lock.
8. SD §15 `realtime`: add `ext-uv` and file-descriptor limits to the Reverb role.
