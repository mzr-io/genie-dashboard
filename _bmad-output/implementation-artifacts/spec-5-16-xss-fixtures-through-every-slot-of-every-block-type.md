## Intent

**Problem:** Nothing proves that every slot of every Block Type shows API content as inert text (Story 5.16; FR-26, FR-32, NFR-4, NFR-7, UX-DR-246, UX-DR-273).

**Approach:** Generate, from the package schemas, a payload for each of the eleven Block Types with every slot filled with hostile text, commit it as the fixture, and render it in the browser tests in the Block, in "View as table" and in the Expanded view.

## Boundaries & Constraints

**Always:** The fixture is derived from the schemas (a new slot is in it, or the test fails naming the slot). `window.__xss` stays undefined, the strings are literal text, and no element in the DOM comes from payload text. Chart tooltips go through the library encoder and no formatter is a string. Very long and bidirectional text is wrapped or truncated by CSS only.

**Never:** No test passes for the wrong reason: the hostile text is asserted to be on the page.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected | Error Handling |
|----------|--------------|----------|----------------|
| Every type | all slots hostile | inert in the Block | N/A |
| Table view | hostile payload | inert cells and headers | N/A |
| Rows page | hostile rows and labels | inert | N/A |
| Tooltip | hostile name and category | encoded | N/A |
| URL token | `javascript:` in a token | percent-encoded, host fixed | N/A |
| New slot | not in the fixture | fails naming it | N/A |
